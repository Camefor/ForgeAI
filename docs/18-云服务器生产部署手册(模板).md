## 2. 发布前检查

> **填写指南**：每次发布前必须手动确认的项。清单未全部通过前，不进入 §4 执行。

- [ ] 本地已在干净 Release 配置下构建通过
- [ ] 全量测试通过（见 `16-测试方案.md`）
- [ ] 本次 PR 已合入主干并打版本 Tag
- [ ] 已通知相关方（如涉及灰度 / 高风险变更）
- [ ] 已阅读本次相关的 ADR 和设计文档

## 3. 服务器登录

> **填写指南**：登录方式（SSH / 跳板机）、认证方式（Key / 2FA）、常用别名或 ProxyCommand 配置。


## 4. 备份

> **填写指南**：发布前的强制备份项。备份失败则停止发布。备份文件命名含任务 ID 和时间戳便于溯源。

```bash
# 数据库备份
<backup-command> \
  --out backups/<project>-<task-id>-$(date +%Y%m%d-%H%M%S).dump

# 验证备份文件非空
test -s backups/<project>-<task-id>-*.dump && echo OK
```

## 5. 同步构件

> **填写指南**：发布的最小文件集。只同步本次需要的目录和配置文件，避免误覆盖生产独有的密钥/配置。

```bash
tar --exclude='<path/to/secrets>' \
    -czf release.tar.gz \
    <src/> <deploy/migrations.sql> <deploy/cleanup.sh>

scp release.tar.gz <user>@<host>:/opt/<project>/
```

## 6. 发布执行

> **填写指南**：按本项目实际的构建、迁移、启动顺序填写。关键步骤的输出做显式检查。

```bash
cd /opt/<project>
tar -xzf release.tar.gz

# 数据库迁移
docker compose run --rm migrate

# 滚动构建与启动
docker compose -f compose.yaml \
  -f compose.production.yaml \
  up -d --build

# 等待健康检查
docker compose ps
```

## 7. 冒烟验证

> **填写指南**：生产可观察的核心路径。失败任意一项触发回滚。

- [ ] 健康检查端点 `GET /live` 返回 200
- [ ] 就绪检查端点 `GET /ready` 返回 200
- [ ] 首页加载成功
- [ ] 核心业务 API 返回 200
- [ ] 关键静态资源加载成功
- [ ] 日志无 Error 级关键字

```bash
curl -fsSL https://<domain>/live
curl -fsSL https://<domain>/ready
```

## 8. 回滚

> **填写指南**：发布失败后的回滚流程。目标：15 分钟内恢复到上一稳定版本。

```bash
# 使用备份恢复数据库（如有迁移）
<restore-command> backups/<上一个稳定备份>

# 切回上一个镜像 Tag
docker compose -f compose.yaml -f compose.production.yaml \
  up -d --no-build --no-deps <service>:<previous-tag>
```

## 9. 清理

> **填写指南**：发布完成后的资源清理。防止磁盘打爆。

```bash
# Docker 清理：悬空镜像、构建缓存、已退出容器、未使用网络
docker system prune -af --volumes=false

# 保留最近 N 份备份，更早的归档
ls -t backups/*.dump | tail -n +<N+1> | xargs rm -f
```
